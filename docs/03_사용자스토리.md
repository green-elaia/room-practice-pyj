# 회의실 예약 서비스 사용자 스토리

## 사용자 스토리

### S1. 겹치는 예약 막기
- 스토리: 회의실을 예약하는 직원으로서, 겹치는 예약이 등록되지 않기를 원한다. 예약 중복을 막기 위해서다.
- 인수 조건:
  - 겹치는 예약을 막는다.
  - 겹침을 판단할 범위와 시간 경계 기준은 **확인 필요**.

### S2. 정원을 넘는 예약 막기
- 스토리: 회의실을 예약하는 직원으로서, 정원을 넘는 예약이 등록되지 않기를 원한다. 회의실 정원을 지키기 위해서다.
- 인수 조건:
  - 정원을 넘는 예약을 막는다.
  - 정원 초과를 판단하는 인원 기준은 **확인 필요**.

### S3. 예약 현황판 웹페이지 만들기
- 스토리: 회의실을 이용하려는 직원으로서, 웹페이지에서 예약 현황을 확인하고 싶다. 회의실 이용 현황을 파악하기 위해서다.
- 인수 조건:
  - 예약 현황판 웹페이지를 제공한다.
  - 현황판의 공개 범위와 표시 항목은 **확인 필요**.

### S4. 예약 취소 기능 만들기
- 스토리: 예약한 직원으로서, 예약을 취소할 수 있기를 원한다. 더 이상 필요하지 않은 예약을 정리하기 위해서다.
- 인수 조건:
  - 예약 취소 기능을 제공한다.
  - 취소할 수 있는 사람과 취소 절차는 **확인 필요**.

## 확인 필요
- **최대 예약 시간(2시간 또는 4시간):** 강도윤 팀장이 정책을 확정해야 함.
- **노쇼 자동 취소 기준(10분 또는 15분) 및 이번 범위 포함 여부:** 총무팀에서 결정해야 함. 회의록에 개별 담당자는 지정되지 않음.
- **현황판에 연락처를 표시할지 여부:** 총무팀에서 결정해야 함. 외부 공개 여부는 강도윤 팀장이 확인해야 함.
